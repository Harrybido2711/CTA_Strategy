# Backtest Prototype

This backtester converts a target dollar exposure into shares, simulates trading, and calculates the resulting portfolio value.

## Column Definitions

| Column                                 | Meaning                                                                                  | Calculation                   |
| -------------------------------------- | ---------------------------------------------------------------------------------------- | ----------------------------- |
| `ts_event`                           | Date or time of the market record                                                        | From market data              |
| `open`, `high`, `low`, `close` | Market prices for the period                                                             | From market data              |
| `volume`                             | Trading volume                                                                           | From market data              |
| `symbol`                             | Instrument ticker, such as SPY                                                           | From market data              |
| `dollar`                             | Desired dollar exposure: positive for long, negative for short, and zero for no position | From the strategy             |
| `target_shrs`                        | Number of shares the strategy wants to hold                                              | `dollar / close`            |
| `curr_shrs`                          | Number of shares currently held in the simulation                                        | Previous row's`target_shrs` |
| `traded_shrs`                        | Shares bought or sold; positive means buy and negative means sell                        | Change in`curr_shrs`        |
| `TWAP`                               | Assumed execution price; this is only an approximation, not a true TWAP                  | `(open + close) / 2`        |
| `cash_spend`                         | Cash used to trade; positive for a purchase and negative for a sale                      | `traded_shrs * TWAP`        |
| `net_cash`                           | Cumulative net cash balance generated by trading                                         | `-cash_spend.cumsum()`      |
| `asset_value`                        | Market value of the current position                                                     | `curr_shrs * close`         |
| `portfolio`                          | Total portfolio value                                                                    | `net_cash + asset_value`    |

`rtype`, `publisher_id`, and `instrument_id` are metadata supplied by the market-data provider. They are not backtest results.

## Target, Traded, Current, and Total

These terms describe different stages of managing a position:

- **Target shares:** the position the strategy wants.
- **Traded shares:** the order needed to move from the old position toward the target.
- **Current shares:** the position actually held after execution.
- **Total value:** the value of the whole account. In this function, it is called `portfolio`.

For example, if the account currently holds 6 shares and the target is 10 shares:

```text
traded shares = 10 - 6 = +4
new current shares = 6 + 4 = 10
```

`traded_shrs` is the amount traded during a period, while `curr_shrs` is the position held after trading.

## Why Are the Values Offset?

In real trading, a position decision and its execution are separate events:

```text
information becomes available
        ↓
calculate target position
        ↓
submit and execute the trade
        ↓
update current position and portfolio value
```

The offset is necessary because:

1. A signal may depend on information that is only available at the end of the period.
2. An order takes time to submit and fill.
3. The actual execution price may differ from the price used to calculate the target.
4. A large order may only be partially filled because of limited liquidity.

For example, if a target uses today's closing price, it cannot realistically be traded at today's earlier opening price. It must be executed at the close or in a later session.

The offset does not always need to be one full day. A pre-market signal may trade at the same day's open, while an intraday signal may trade seconds or minutes later. The correct timing depends on when the information becomes available and when execution is possible.

## Timing in This Backtester

This implementation creates two offsets.

First, the signal date is delayed:

```python
dollar['ts_event'] = dollar['ts_event'] + delay
```

With the default one-day delay, a signal dated January 2 becomes available on January 3.

Second, the target position is shifted by one data row:

```python
df['curr_shrs'] = df['target_shrs'].shift()
```

Therefore, the January 3 target becomes the current position on the next trading row, January 6:

| Date  | `dollar` | `target_shrs` | `curr_shrs` | `traded_shrs` |
| ----- | ---------: | --------------: | ------------: | --------------: |
| Jan 2 |    `NaN` |         `NaN` |       `NaN` |         `NaN` |
| Jan 3 |          1 |        0.003099 |       `NaN` |         `NaN` |
| Jan 6 |          1 |        0.003093 |      0.003099 |        0.003099 |
| Jan 7 |          1 |        0.003130 |      0.003093 |       -0.000006 |

The full timeline is:

```text
Jan 2: signal is generated
   ↓ one-calendar-day delay
Jan 3: dollar and target_shrs appear
   ↓ one-row shift
Jan 6: the target becomes curr_shrs and produces traded_shrs
```

`diff()` does not add another delay. It only calculates the position change:

```python
traded_shrs[t] = curr_shrs[t] - curr_shrs[t-1]
```

Because both `delay` and `shift()` create an offset, the current code may delay execution twice. Whether both are necessary depends on the intended signal and execution timeline.

Also, `target_shrs = dollar / close` changes whenever the closing price changes, even when `dollar` stays at 1. The backtester therefore makes small daily rebalancing trades to maintain the same dollar exposure.

The correct economic order should always be:

```text
target decision → trade execution → current position → portfolio valuation
```
